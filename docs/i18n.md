# BASIC language architecture

`src/i18n.js` owns the RO/EN dictionaries, initial language detection, preference persistence, text interpolation, calendar month/weekday names and static DOM translations. Domain/storage/calendar geometry use exactly the same data and algorithms. Existing domain errors are translated at the UI boundary through a central error-to-key map. User-entered names, addresses, cities, phone numbers and ISO dates are never translated or rewritten when changing language.

On first launch a Romanian device locale (`ro` or `ro-*`) selects RO. English and unsupported device locales select EN. A valid manual choice takes precedence and is stored under the separate `apartment-booking-manager:language` key. Booking storage stays at `apartment-booking-manager:v1`. Dates display and accept DD/MM/YYYY in both languages.

RO | EN controls are available in the header and modal forms/confirmations. Switching language updates labels, messages and calendar text without resetting draft input values or changing the displayed period. The editor uses centralized required-field messages instead of OS-language-dependent native validation popups; domain date/order/phone/overlap validation remains intact.

To add a language, add a dictionary with the same keys, twelve month names and seven weekdays, its initial-locale rule if required, and its language-control metadata. No duplicate pages are needed. Dictionary parity tests catch missing keys.
